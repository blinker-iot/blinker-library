# Device V2 BLE 首连分段优化

更新：2026-10-13。现有任务与 Sketch timer 的 T3-1～T3-5 已限定收口；本阶段 B1～B4 的软件修正、COM3 有限短验收及默认策略决策也已收口。只改善既有 BLE 前台首连，不扩槽、升级 SDK、修改安全准入或重造通信链。普通默认仍关闭可选窗口；软件通过、现场样本和全平台推广分开，不把旧样本算成本轮收益。

## 1 已有证据与实施选择

首连按发现、原生连接准备、鉴权、Manifest 接受、fresh State 和页面可控分段。Android 原生 connect 包含连接、服务发现和 MTU 交换；getServices 只读取已经发现的列表，不能将二者误记成物理建链和服务发现的独立耗时。没有独立观测的阶段不反算。

原 [易用性方案§8.3～§8.4](DEVICE_V2_CORE_USABILITY_OPTIMIZATION_EXECUTION_PLAN.md#83-测量修正与三次已有设备短验收) 已明确：20 B peer 的瓶颈主要是认证期串行 native write，设备发送端没有重复的 30 ms sleep。已实现的 Manifest 缓存、MTU／数据长度协商、20 B 回退、失败 BLE 候选不阻塞 Cloud 和有界 HIGH／BALANCED 窗口直接复用，不重新实现。

旧同设备 A/B/B/A 两次均值为 3260→2785 ms，但只有 20 B peer 的有限趋势，不是本轮或全平台收益。现有窗口不等待原生提示，回应预算 250 ms、总窗口 5 秒；就绪恢复 BALANCED，取消／断开由原 generation 和 admission 栅栏隔离迟到结果。原生 API 成功只证明提示结算，不证明实际空口连接间隔、DLE 或 PHY。

本批先补窗口收尾的真实一致性缺口：普通 `connect()` 在完成同步后收尾，但 `connectEphemeral()`、`resume()` 和认领入口依赖截止或断开。统一收尾不改变鉴权、认领提交、secret 清除或 fresh State 条件，也不声称这就是普通首连的主要延迟来源。

## 2 本阶段顺序

| 步骤 | 范围 | 准入与验收 | 状态 |
| --- | --- | --- | --- |
| B1 | 统一既有窗口收尾；补 ESP32 四槽 RX 背压回归 | 各入口成功／失败保持原同步与秘密清除；四包接收、第五包明确拒绝、poll 后恢复容量；不扩槽 | 完成，见§5 |
| B2 | 匹配 App 软件门禁和明确候选 | 复用既有 maintainer-only 窗口配置；native 拒绝／缺失／不结算不得阻塞，iOS／web 跳过；普通默认先不变 | 完成：匹配 APK、保留数据安装及§5门禁 |
| B3 | 有限分段短验收 | 原授权广播未匹配后，用户另行批准 COM3 新鲜备份、临时认领和恢复；真实 Method2、Manifest ACK、fresh State、窗口与离页回收 | 完成：同一 S3 的 A/B 两窗、B 控制及恢复，见§6 |
| B4 | 决定普通前台策略与更新当前入口 | 实测与推广分开；不将候选配置／旧收益冒充普通默认准入 | 已决策：显式候选保留，普通默认不变；不追加循环，见§7 |

真实测量优先选择当前账号具有 active credential、由授权 Presence locator 匹配的设备，不凭名称、MAC 或扫描先后选板。串口和 MAC 仅用于需刷板时的防误操作；默认不刷板／清授权，实际临时候选须另有明确批准。最多有限短进入，轮间遵守扫描预算，不跑 100 次或长稳循环。

## 3 模块与资源边界

- 连接参数提示只属于 App 的原生 BLE link，独立于 MQTT、设备逻辑身份、授权和页面模型；不放进 MCU 协议或服务器。
- 保持 20 B 启动／Noise／Method2／Hello 响应合同；只有现有 authenticated Hello 确认后才使用大包。MTU、广播能力或设备名不能代替确认。
- 保持 ATT20 的 30 ms 消费间隔和大包后的既有 10 ms 节奏；不切换无确认写入、不并发碎片、不增加队列或消费槽。
- 保持 ESP32 入队后 ATT success、满队列明确拒绝，以及确定未发送的 CapacityExceeded 原密文回退；未知写入结果不重放业务。
- Cloud 仍复用唯一账号 MQTT；退出页面回收本地候选／连接和页面 interest，不关闭常驻账号 MQTT。纯认领、网关路由、LAN、任务、自动化及历史不搭车扩展。

## 4 验收口径

普通工具只记录阶段和相对时长、成功／固定拒绝类别、记录字节及片数，不保留密钥、地址、payload 或异常正文。原函数、Promise、权限与状态都不替换；退出后移除观察器并检查 opening、页面 group 和本地连接。缓存命中仍需真实 ManifestAccept ACK 和 fresh State，接收字节不等于已认证或可控。

App 更新使用保留数据安装，保留原 APK、账号及完整请求日志；服务沿用当前健康环境，不为纯 BLE 测量重新部署。若实际发现需要固件候选，先另做本次新鲜完整备份，限定一块板、应用范围和授权恢复，再执行。测量不自动认领、旋转 Key、Start 任务或重放 Action。

本阶段不会承诺秒开、无缝 SLA、跨 SDK／iOS／R4／Wio 全面加速。定时、实时、H1 等已通过项不重新排队；自动化扩展、H2、OTA、离线历史／Bulk 和新网关协议继续后置。

## 5 软件结果与现场边界

App 只修正现有 `ble-direct/client.ts` 的四个入口收尾，生产差异为 7 行增加、1 行替换：认领、临时凭据连接和恢复入口补原 `finishBootstrap()`，普通连接的可选提示异常不再覆盖业务结果或阻止 secret 清除。未新增 wrapper、状态机、环境开关或另一份窗口；commit、active save、Method2 和同步顺序不变，调用方拥有的临时凭据不被擅自擦除。

四套定点回归共 57/57 通过，spec TypeScript、定点 lint 和 diff-check 通过。测试覆盖成功／失败、认领提交与保存先于同步、输入／存储拒绝未获取连接时不结束窗口、提示同步抛错及已有缺失／拒绝／不结算、iOS／web 跳过和迟到代际取消。初次新增测试的 API 夹具缺少 unused 方法，修正夹具后通过类型检查，产品 API 未为测试改动。

设备端只补 `tests/host/test_esp32_nimble_main.cpp`：保持默认四槽，四次 ATT 接收成功，第五次明确返回 `BLE_ATT_ERR_INSUFFICIENT_RES`；限定每 poll 消费一包，释放一槽后接受原被拒包，最终 FIFO 投递五包且每包只一次，没有断连或 host 重启。该目标完整链接、ASAN CTest 1/1 通过。首次直接运行因子进程缺现有 ASAN DLL 搜索路径未启动，补子进程路径后通过；未修改系统或 SDK 配置，不计为性能提速。

现场初查使用前批已安装普通 App，先完成本次 APK 和完整账号／请求日志备份；手机蓝牙、前台、首页和设备数据均就绪。当前五个已有凭据候选没有“附近”证据，对以前已验证且仍有凭据的精确逻辑身份做一次授权 locator 扫描，约 5026 ms 后返回 scan-timeout，没有 native connect、GATT、认证或控制写入。该失败只表示未匹配到此身份，不能推断所有现场板都未广播，也不是新版窗口的性能测量。退出后页面 group／本地 link／session／opening 为 0，观察器移除，原 19 台设备和账号保留；没有刷板、认领、清授权或部署服务。

普通环境仍关闭可选窗口。B2 使用既有 `local,ble-priority-test` 维护者候选：类型检查、Web 和 offline 单 worker Android 构建完成，未升级 SDK／依赖或切换 WebView origin；真实 APK SHA-256 为 `ad1ffe5e9cc36d1229d62fd5c2ec552dbbd7c7086c89062aa7b8a50213d1d3b2`。第一次构建适配器因文本计数检查停止，只通过此前类型／Web 步骤，未算 Android 成功；保留失败记录后纠正检查，另建本次匹配 APK。候选存在不等于普通默认准入。

## 6 COM3 同条件短验收与恢复

用户明确批准仅使用 COM3 做有限候选。先新鲜读取整片 8,388,608 B Flash 并设备校验，SHA-256 为 `5677f4158247f0cb561d7a4f03e15bf4e208b1726c0e4da304beaebc584d6d94`。复用现有 ESP32 core 3.3.11 完整链接普通 BLE 候选，仅加入维护者公开验签/profile 与隔离测试存储命名空间；应用 BIN 698,032 B，实际程序 697,888 B、静态 RAM 35,984 B，符合原物理 app0 的 1,310,720 B 限制。只写 app0，不改 bootloader／分区表，不使用旧 Flash 备份或注入授权。COM11 和 UNO R4 未刷写。

现场存在三个同类广播，先通过 COM3 进入 ROM 后候选消失、正常启动后同一候选返回的实际对照确认物理载体。正常 App 认领的首次真实 issue 请求在委托前核对 ROM/NVS 公共实例；accessEpoch 来自真实 Hello 的随机值，不固定填 1，不用 MAC 作为逻辑身份。实际 issue／commit、active receipt-backed credential、Manifest accepted 和 fresh State 一致后解除观察器。自动进入控制页后正常退出，约 194 ms 释放页面及本地连接，原 19 台设备保持。

A/B 在同一新认领设备、固件、App、授权及命中缓存下执行，各仅一次，轮间至少 35 秒。A 只关闭该连接现有窗口，B 使用维护配置原有窗口；两次结束都恢复原 descriptor，未改生产开关或另一条连接链。双方都在真实鉴权后接受 244 B，bootstrap 仍是 ATT20。

单对样本观察差为 363 ms（14.3%），不是稳定收益或 SLA。GATT 的 173 ms 差异发生在 HIGH 提交之前，不能归因窗口；认证前 15 次 native write 总耗时 826→688 ms，方向与窗口收益一致，但仍只是这一块 S3 的观察。四条 bootstrap 记录共 15 片，既有片间等待合计约 330 ms 未改变。窗口不会缩短此前的发现或原生连接准备，也未证明独立的空口参数或芯片计算耗时。

B 的 HIGH／BALANCED 实际提交为 1→0，分别约 7.7／6.9 ms 结算；两次提交间隔约 1175.8 ms，不能称 API 结算耗时或空口连接间隔。双方真实命中缓存仍完成 ManifestAccept ACK 和 fresh State，事件无丢失、同一账号 MQTT 会话保持。仅 B 执行一次普通电源和按钮控制，真实 ACK 约 56／53 ms；State revision 1→3、power false→true、buttonPresses 0→1，无 Action 重放。两窗退出后 group／link／session／opening 均为 0，观察器移除，原 descriptor 恢复。

收尾通过普通 App 入口仅移除本次新 BLE 设备：一次真实 DELETE 200，Cloud 授权 revoked，`localAccess=not_confirmed`。不宣称设备收到撤权确认；设备端恢复是另一份独立证据。原 19 台 ID／UUID 和账号保留，没有任务 HTTP 或数据库回滚。

从本次完整备份恢复 `0x9000` 起的 1,339,392 B 原 NVS／启动状态／app0 范围，设备 digest 校验并正常启动；原固件和授权恢复。未写 bootloader／分区表，不称恢复后重新读回整片 8 MB 或原旧网络配置重新上线。原普通 App 以保留数据安装恢复，实际 APK SHA-256 为 `f2bc1828c3fb8d03ea72fcd58bd323daa90bca2b8e16024e9e0b6033b72524ff`；恢复后再次核对原账号和 19 台设备。原始、真实认领／控制后及收尾后的完整 App 数据分别私有归档并校验，不用旧 tar 覆盖新请求记录；只移除本批自有 USB 转发。

本批证据在忽略目录 `build/ble-first-segment-20261013/`，收尾复核为 `acceptance.json`：App 1,573 项及设备运行时 410 项冻结输入摘要不变，三端 HEAD 未变。首次普通 App 扫描失败、构建计数检查失败及正常离页夹具的 null／undefined UUID 检查早停分别保留；后者未发导航或业务请求，只读核对后按原认领守卫的 `?? null` 规则有限纠正，没有放宽设备存在性要求。不把这些失败覆盖或计为性能通过。

收尾发现私有 A/B 工具原冷却检查误将文件名前缀 `b3` 的数字当作时间戳。另按文件末尾锚点及两个完成样本复核，实际 A 收尾→B 开始为 46,756 ms，满足 35 秒预算；不把原错误检查当通过依据。先归档实际测量时的源码，再有限修正正则并做本地检查，两个样本的原摘要与记录保留；计划已关闭，不重复实物。私有 Flash、App 数据、账号／网络配置、APK、一次性工具和编译产物不进入公开交付。

## 7 收口决策与后续边界

B1～B4 的本批有限范围已关闭。保留现有维护者显式窗口候选，普通环境仍为 `false`；单次 A/B 及 S3 不足以推广成全平台默认，本轮不为凑结论追加循环、升级 SDK 或移除安全准入。认领实际成功不等于首次 Noise 各阶段性能已测；R4／Wio、iOS、长稳、生产默认和普遍秒开均未新增证明。

当前主要剩余时段仍是原生 GATT 准备和 ATT20 认证串行写入，而不是缺另一条 MQTT、后台预连接或增加 RX 槽。若后续明确要求再缩短，另限定评估载体能力与认证启动阶段的协议兼容边界，不能直接全局删 30 ms 等待、提前信任广播包长或并发 GATT 写入。本批不实施该扩展。

回到已有功能的必要源码审阅／交付和真实反馈；不重开已通过任务、N1～N5、实时／H1 或 BLE 循环。自动化扩展、H2 仍按原计划独立排期；自定义控制页面 V2 由同事处理，OTA／离线历史／Bulk／复杂规则／新网关继续后置。SDK、服务镜像和数据库沿用；本批未暂存、提交或推送，无关本地修改保持。
