## 2. 第一性原理与模块边界

1. 时间只回答“现在/经过多久”；任务决定“何时做”；动作入口决定“可不可以做、怎么做”。
2. 手机编辑/显示配置，不是持续执行器；关闭页面不能取消已经安装的本机任务。
3. 一条任务只有一个执行方，网络通道不是执行方；云端和网关不同时运行同一规则。
4. 复用设备模型与写入回调，不复制一套 GPIO/状态模型；report 只上报，不能代替物理执行。
5. 用到期任务表而非每任务一个线程；固定容量、有限回调、明确错误，默认不启用。
6. “共同合同”不等于强求 MCU C++ 与服务器 TypeScript 共用同一运行时；复用语义、数据向量与验收标准。

| 模块/职责（设计名，非现有 API） | 输入/输出 | 不包含 |
| --- | --- | --- |
| 业务时间源 | 单调 tick、有效 UTC、年龄/误差 → 时间快照 | 规则、网络、所有权判断 |
| 本机任务核心 | 有界任务定义＋时间 → 到期执行请求 | MQTT/BLE、页面、动态脚本、Flash 驱动 |
| 任务存储适配 | 版本化配置/必要执行检查点 → 原子提交/读取 | 执行条件判断、网络重试 |
| 本机动作适配 | 已安装且授权范围内的目标 → 共用校验/写入逻辑 | 伪造 RxContext、绕过范围检查、直接改 State 假装成功 |
| 任务管理适配 | 已授权操作、版本和请求标识 → 校验/持久化回执 | 另一条传输或另一套设备身份 |
| App 任务/规则服务 | 类型化 CRUD、真实回执 → 页面状态 | 旧 JSON 转发、常驻执行、以本地缓存冒充设备确认 |
| 云端规则执行模块 | 经验证的新鲜状态＋规则＋权限 → 受限命令/执行记录 | Broker 热路径内执行复杂规则、借用用户 bearer token |

优先在现有层内补小模块。只在确有调用方时提取公共动作校验入口，不新建“全局协调器”；composition 仅负责可选注入，begin/组件 API 保持现状。

## 3. P1：BLE 性能包

### 3.1 基线与测量

[9 月 18 日报告](DEVICE_V2_FIRST_CONNECT_OPTIMIZATION_REPORT.md)中的同设备命中样本：GATT 780 ms、认证 933 ms、Manifest 481 ms、State 272 ms、页面 ready 2,958 ms。阶段不必精确相加，外围准备/调度另计；有限样本不能当作分位数或 SLA。

P1 先记录扫描、连接、服务发现、通知订阅、每条握手报文、每片发送/接收、设备消费时刻、ACK、State。区分 CPU 计算、原生调用、显式等待与空口等待。读取实际 MTU/连接间隔/队列溢出计数，不能只记录请求值。

同设备/手机/固件作少量交替对照，覆盖已绑定无缓存、缓存命中、退出取消和 Cloud 候选不被阻塞。保留不利样本；初次认领包含不同授权步骤，不能与重连混成同一延迟。没有收益或证据不足即结束本包，不自动转 100 次循环。

### 3.2 先保持 wire 不变

- 排查重复服务准备、无必要的串行等待、过慢实际连接参数；SDK/手机不接受参数时仍正确工作。
- 不盲目缓存 GATT handle，不去掉固件变化后的服务合同校验。
- 现有 30 ms 等待兼顾无线协处理器消费。移除前必须证明 RX 可消费/有背压且取消正确；GATT write 成功不代表 MCU 已处理。
- 认证保留；缓存仍须真实 ManifestAccept ACK 和 fresh State，不能通过提前 ready 伪造提速。
- 不更换 NimBLE 实现、不强绑新 SDK、不预连所有设备、不将网络通道切换当重复执行许可。

### 3.3 P2 候选：仅在收益成立后立项

20 B packet 扣 4 B 头后每片承载 16 B；160 B record 需要 10 片，仅 9 次显式等待就达 270 ms。这是候选优化依据，不是端到端收益预测。

若 P1 证明分片占主要瓶颈，再评审“可协商 packet 上限/发送节奏”。必须核对两端 GATT 能力、实际 ATT payload、缓冲和消费速率；共同采用有界值，不以广播设备名决定高速模式。不能单边按 MTU 放大或随便改现有宏。

旧端/初始握手保持原 20 B 合同；切换需明确版本、切换边界及回退，不能破坏鉴权 transcript 或让未认证数据授予权限。若只在鉴权后切换，就不声称已经改善前置认证的全部耗时。

P2 不属于默认执行队列；需给出预计往返收益、三端协议影响、各端峰值内存、R4/Wio 保守兼容测试。不能仅因 ESP32 成功就改变所有产品。

## 4. T0/T1：本机任务合同

### 4.0 分阶段冻结，先验证不依赖授权的时间计算

T0 拆为 **T0a 时间计算**与 **T0b 执行/管理合同**；T1 拆为 **T1a 时间原语**与 **T1b 执行器及存储/动作接线**。T1a 可在 T0b 尚未冻结时独立实现，因为它既不授权、也不写属性或宣告协议能力。不能以此跳过后续权限和掉电语义。

本批已实现内部 [TaskTiming](../src/BlinkerV2/core/TaskTiming.h)：

- `Countdown`：持续 `1..2^31-1 ms`；8 B 易失单调状态；活动中再次 start 拒绝，不重启截止点。poll 一次消费到期，loop 迟到最多 1,000 ms，超过则 Skipped；这是调度宽限而非 UTC 精度承诺。
- `UtcOnce`：沿用业务时间 `[2000-01-01,2100-01-01)`，单位毫秒；`Weekly`：周一至周日 bit mask、分钟 `0..1439`、固定偏移 `-720..840` 分钟；每日复用七天 mask。未使用字段必须为零。
- `nextTaskUtc` 严格返回输入游标**之后**的下一时刻；最多检查八个本地日期，不使用平台时区/libc 日历。它不决定当前时钟是否可信、是否错过或是否已经消费。调用方不能每轮仅传入当前 UTC，否则可能漏掉到期点。
- 单调倒计时遇到可识别的 tick 倒退/超过半周期的间隔返回 Interrupted；已知 tick 重置/不可测睡眠必须由调用方 cancel，无法凭一个 32 位 tick 检测未观测的整周回绕。重启默认 inactive，不从 Flash 恢复运行截止点。
- 这不是 wire 编码、任务表或公共用户 API。未加入 `Blinker.begin()`、新 feature/kind、存储或系统线程；完整容量、值区与持久执行游标仍待 T1b 测量。

T0b 必须先补：同一 WallClock 快照的准入与校正事件、已消费高水位/重启处理、owner 可验证管理权限、请求/定义版本、存储原子性与动作幂等边界。当前 Control 位不能证明 owner；不能先接一个未经验证的“安装任务”入口再补权限。

具体落实到[执行器设计](DEVICE_V2_TASK_EXECUTOR_DESIGN.md)：T0b-1 已确定四个模块、定义/进度/易失状态、一张原子任务快照及 Claim-before-apply 的掉电边界。后续已补时间样本/cursor、快照/故障锁定，以及独立scope、Grant、严格wire/golden、来源adapter和可选生命周期。T0b-2尚需实际BBP分发/平台根事件、权威签发与App/Service消费者；内部底座通过仍不允许提前宣告公开任务管理能力。

### 4.1 四种时间需求分开

| 类型 | 首版规则 | 持久化/恢复 |
| --- | --- | --- |
| Sketch 周期回调 | 单调时间；错过周期合并/跳过，不突发补执行 | 默认易失；不将开发者回调指针持久化；公共 Timer API 非首版必需 |
| 用户倒计时 | 单调截止点；断网/页面退出不停止 | 配置可保存，运行状态绑定启动代际；重启中止，必须显式重新启动 |
| 一次日期任务 | 有效 UTC；指定截止点 | 保存任务；重启待校时；过期不补执行 |
| 每日/每周 | 任务固定时区偏移＋本地日历时刻 | 保存规则；选下一次未执行 occurrence，错过不补发 |

首次 T1 只支持**单目标、显式允许调度的属性赋值**；值类型/约束复用 Manifest。读写属性不天然意味着无副作用，应由固件开发者明确允许调度。非幂等 Action/多步循环/随机/日出日落/完整 cron 后置。

端点持久引用用稳定 key 与预期类型/访问合同，不保存会话 ID-mode 索引；加载/执行前解析。固件摘要变化后重新校验：无关端点变化不必删除全部任务，目标删除/类型或权限变化则暂停并说明原因。

### 4.2 时间有效性与离线边界

保持一套业务 WallClock，使用同一快照中的 UTC/误差/年龄；不复制一个“永不过期的定时时钟”，不修改安全 IClock 或系统 TLS 时间。

- 现有一小时是上限，不是保证：样本误差也会使时钟提前过期。`enableTime()` 当前不公开持有期配置，延长策略需要实现与测量，不是已有能力。
- 首版日历任务仅在时间满足任务允许误差且来源/保持策略有效时执行；否则 WaitingForTime，获得新样本后跳过已错过 occurrence。
- T0 评估并记录所支持产品的默认任务精度、最长离线保持期和刷新来源。单纯提高 maxAge 不解决漂移、误差上限和断电问题；未经校准不能调低 driftPpm 来“通过”。
- 纯 BLE 配好后若需数天离线日历运行，必须有验证过的保持预算或可选 RTC/网关来源；未实现前 UI 明示条件，不把仅短离线验证称为该需求通过。
- 断电后无 RTC/外部有效样本，日历等待；RTC 作为可选来源由平台适配，普通功能不强制用户购买硬件。Flash 里的旧 UTC 不是当前时间。
- 可检测 tick 重置/不可测深睡眠清时间；任务单调截止采用安全回绕算法和明确最大间隔，不用有符号溢出或 32 位 long 存长期日期。

首版固定偏移在任务创建时保存，不随手机当前时区自动变化。不支持的夏令时区域明确拒绝/提示固定偏移含义，不冒充 IANA 全时区；未来区域时区/有限 UTC 日程另行评审。

### 4.3 触发、校时和重启

- 由截止点跨越触发，不做 `hour == 8 && minute == 0` 式每轮重复执行。每轮最多执行有限任务，用户回调必须非阻塞。
- occurrence 由任务 ID、定义版本和逻辑截止点标识；UTC 回拨不重复已消费 occurrence，前跳/重启错过默认跳过。正常 loop 抖动允许有限迟到，容忍上限和校时事件区分在 T0 冻结，不能无限补偿。
- 单调倒计时不被 UTC 校正改变。网络 reconnect 不重置倒计时；恢复出厂、重启或显式启动是不同事件。
- 先记录持久执行意图、再执行、再记录结果时，断电仍可能留下“未知”；不能声称 Flash 和物理动作原子。恢复后不自动重放未知动作；幂等属性也不能绕过用户回调的副作用限制。
- 同时到期按固定稳定顺序处理；用户/定时写入走同一执行入口。安全联锁始终优先；一次手动控制默认不删除任务，App 可显式停用。
- 状态保留最近结果和计数即可；首版不引入设备端无限日志。结果 ACK 表示入口接受/返回成功，不冒充传感器证明物理动作完成。

### 4.4 存储与资源

建议从 4/8 个固定任务容量探针开始，描述、运行槽和紧凑值区分；最终默认容量及每任务 RAM/Flash/栈预算由 T1 的 32 位 ABI/真实编译决定，不先承诺某个未测字节数。

配置用版本、完整性校验及原子提交；CRC 只检测损坏，不是权限证明。复用现有存储端口，只有不满足原子替换时才添加小适配，不在协议层判断 EEPROM/NVS/外部 Flash。

仅配置变化和必要 occurrence 检查点写入，不逐秒持久化剩余时间；首版对持久任务设置执行频率/写入预算。确认写入失败时不得回复“设备已保存”。磨损、断电恢复、容量满、损坏回退必须测试。

未启用无整表/队列/持久日志成本；每轮工作有界，不按连接数复制任务引擎，不新增独立 RTOS task。网络 SDK 或用户回调若阻塞，会影响调度，不能宣称硬实时。

## 5. T0/T2：三端任务管理与权限

### 5.1 一个合同、相同承载

逻辑操作为读取能力/分页列表、创建/修改、启停/显式启动、删除、读取状态。以 BBP/2 可选系统能力接线，MQTT/授权 BLE/后续 LAN 复用同一语义，不新增 JSON 定时双栈或把任务塞进用户保留组件 key。

T0 产物需列出字段、上限、状态/error、请求幂等、版本竞争、Golden 向量及三端 kind/feature 空位核对；**本文不擅自分配数字或发布不存在的 API**。能力只能在存储、权限、执行三者接齐后宣告。

逻辑字段最少包含：任务 ID/版本、类型、启用状态、时间参数、目标 key/类型/有界值、允许迟到/错过策略；运行结果单列。ownership scope 来自已验证执行上下文/本机根，不接受请求 body 自称 owner。UTC/持续时长单位在 wire 明确，不混用秒/毫秒。

### 5.2 首版减少多端冲突

- 设备已提交配置是实际执行依据；首版只在线安装任务。App 离线编辑可留草稿，但不显示生效，也不在未来重连时静默安装。
- 服务可保存草稿/已确认镜像，不能同时按同一任务另发到期命令。手机切 Cloud/BLE 只换投递通道，不建立两份任务。
- 修改使用 expected revision；相同请求重传返回相同结果，不重复启动倒计时。明确区分“设置为启用”和“重新开始”。删除与启动也受版本控制，迟到请求不能复活任务。
- 未知结果先查询设备状态再决定下一步，不换 requestId 盲重发。单次任务配置保持原子；首版不做全量多任务事务。
- 分别显示 Draft、Pending、Installed，以及 Disabled/WaitingForTime/Armed/Completed/Interrupted/Error；网络送达、落盘确认和业务执行结果不同。

### 5.3 谁可以安装长期任务

首版仅 owner 管理，普通只读/控制分享不包含持久任务管理权。**现有“可以控制”不是可证明 owner 身份的替代。** T0 必须核对 Cloud 与 Direct 的实际权限映射；若共享凭据无法区分 owner，不允许在该通道直接开放管理。应使用可验证的 owner 专用授权操作或限制入口，不能只靠 App 隐藏按钮。

任务绑定独立随机 128-bit task scope（逻辑设备＋物理 instance＋所有权任期），不是两条认领路径的 accessEpoch 或 Key 版本。schema 2 已原子保存 instance/scope/rootDigest；正常重启/重连且实际根匹配时可恢复；同 owner 换根先暂停，经可信 CAS 更新后保留定义，不先运行后校验。Pending 与 Retired 分开，授权间隙后不补跑日历/重开倒计时。普通WiFi owner/根映射和签发来源已在后续批次接线，不能用表头自证有效；BLE/混合根不因该结果而准入。云端删除时应停用相关云规则（A1尚未实现），本机退休仍依赖实际收到并执行，不承诺离线瞬时撤销。

为避免当前阶段复杂化，不支持分享用户安装持久任务、不做后台自动恢复已删除任务。新所有者不能继承旧任务和执行历史中的私人内容。

第十批将两通道统一为**设备挑战＋服务器签名任务授权**，不再为 Direct 单独保存 Admin 会话元数据。初始化、安装/修改/启停/删除、读取设备任务都需要 App 可访问服务；BLE 设备无需自行联网，已装任务的离线执行/时间限制不变。Grant v1 body 最大176 B、含路由/BBP/CRC 为235 B，候选 Prepare 为182 B；复用现有 codec/验签接口，不加大公共 buffer。内部 C++/独立 Node golden 已过，第十一批已补持久 binding 和等待/根 CAS；生产根证明、nonce 的单次消费/超时、可信回执/分页、服务真实 owner 签发仍未完成，不能作为生产准入。具体合同及跨产品生命周期见[执行器 §8.6](DEVICE_V2_TASK_EXECUTOR_DESIGN.md#86-第十批统一签名管理与独立-task-scope2026-09-23)。

| 端 | 首版必需 | 清理范围 |

### 6.2 触发语义与数据需求

- 首次读取、进程重启、重连快照建立基线，不默认当作一次变化。只对随后收到且满足新鲜度的观测变化触发；不保证捕获采样间或 State 合并丢掉的所有瞬态。
- 阈值扩展使用回差、边沿及冷却；重复State、重连或回放不能反复触发。首轮只认实际携带源key的已验收变化，整份State updatedAt不能证明该key新鲜。过期记录、断线/观察缺口要重新建基线；连续在线但值不变无需伪造同值心跳，旧缓存不能产生新触发。
- 页面实时lease与自动化需求分开。首轮规则取得Broker有界状态观察租约，停用/撤权释放，App退出不释放；不创建假的App会话或增加MCU采样流，不解除总体限流。
- 首轮只消费已有变化上报，新鲜度为Broker接收变化的年龄，不保证传感器物理采样年龄。额外采样要另接既有Telemetry需求合并/限额/租约；不在A1首轮承诺。服务重启重新建立有效观察基线，不补触发或残留无界owner。
- 当前普通 Event 不代表持久可重放事件总线。要求“一次按钮绝不遗漏”等事件型规则时，须先定义 event identity、持久接收、去重/顺序与保留期；不在 A1 内冒充已满足。

### 6.3 授权、可靠性和闭环

规则配置/执行时均校验源可读、目标可控和当前 ownership/版本；规则停用、设备删除或权限变化须同时停订阅、废止待执行动作。不是只在创建时校验一次。

先做同 owner 范围；跨账号分享触发和目标授权后置。执行端使用受限服务身份，复用已授权命令链，但必须补齐服务主体合同；不借手机 token、不使用 Broker 管理权限绕过业务 ACL。

已有 command ledger/replay ACK 可复用，但不能证明自动化的触发只发生一次。最少增加规则执行记录与幂等标识，覆盖“持久认领执行→发命令→确认/未知”，进程崩溃重启不把同一执行变成新命令。跨进程/跨分片只允许一个有效执行 owner，初期不自动迁移到网关。

动作TTL到期或目标离线不无限排队；已进入投递边界的超时/崩溃是unknown而不是“肯定没执行”。仅原活跃Broker会话可受截止/逐次准入约束重传exact原帧，恢复只读查询原ledger，不换ID/会话补发。同值赋值也可能触发有副作用的回调。ACK、观察到新State和外部物理效果分别记录。

最少加入回路防护：首轮服务端事务拒绝同设备源/目标、设备级环及多条规则的目标冲突，暂不允许目标设备再作为另一规则源。不能假定不同Property不会由Sketch相互影响。多跳须另有因果标识传播/深度限制后才开放，不能只靠冷却把循环变慢。

云端规则模块独立于Broker热路径。已选择Gateway PG保存规则/执行两张业务表，复用有界worker；Broker保留唯一command ledger，不复制Task/LocalAccess专用outbox。内部签名只证明调用者，新增窄业务准入负责规则/owner/精确目标及每次发送截止。停用阻止提交后的新准入，不承诺召回此前已准入网络包。详细并发/持久化与门禁只维护在专项，避免三份合同分叉。
