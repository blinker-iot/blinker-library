## 2 版本和模块边界

开始时设备库 `device_v2` 为 `31f7e04`，App `i3w-dev-v2` 为 `11bf848`，IoT Service `dev_v2` 为 `268a1d1`。本批主修改在 App 页面/纯展示模型和设备仓的测试工具。Service、设备固件、SDK、原生插件和依赖锁不需要因这些页面问题升级。

职责保持如下：

- DeviceUiPort 与既有连接协调器决定实际通道、当前状态和控制准入；页面只解释这些证据，不新建状态机。
- 数值提交复用现有 command 和值校验；页面空输入不是合法数字 0。
- 自动化选择项和引导从现有设备/Manifest 缓存投影；不会在打开自动化页时扫描、连接或获取全部设备。
- 任务展示不修改持久请求日志、服务账本、授权同步、任务容量或执行时机。
- BLE 工具仅观察真实调用的起止及结果类别，不替换响应、伪造 ready、注入凭据或自动重放 Action。

无关本地修改保留；不清除账号、设备授权和原请求日志，不提交或推送。本批不生成本地交接包。

## 3 控制输入和连接状态

### U1 数值提交

数值输入为 `''` 或仅空白时，显示输入错误并返回，不能调用发送函数。显式 `0` 与带前后空白的合法数字继续按既有合同验证。文本输入不受此数值保护影响。整数仍需安全整数、类型宽度、min/max/step 等既有校验，不新增浮点规则。

回归覆盖空串、空白、显式 0、合法非零整数、非法整数和原布尔控制；至少一个真实模板提交断言零 command，避免仅验证辅助函数。

### U2 当前通道

连接名称以 `activeTransport` 为依据，不从“是否 BLE”推导剩余全部是 Cloud。已连接/可通信仍要求当前页面连接有效、就绪且有 fresh State；广播附近、云端在线和直接可控制是不同事实。

测试覆盖 BLE/LAN/Cloud、ready 到 ready 的通道变化、失去 fresh State、正在同步、重连与离线。Cloud presence 只能表达云端证据，不能覆盖所选本地通道状态。事件别名只在 key/kind/type 匹配时使用；未知或旧类型回退原 key，不更改权限、事件值或设备协议。

## 4 自动化引导和任务异常态

### U3 自动化能力引导

沿用当前普通所属 WiFi 设备范围与 bool/uint32 单动作准入，分别说明条件和动作缺项：

- 属于当前支持设备，但没有缓存 Manifest：先进入该设备控制页获取能力。
- 已获取能力但没有可用条件或动作：说明当前固件没有相应许可属性。
- 分享、纯 BLE、网关/子设备或其他未准入范围：明确当前不支持，不提供会暗示支持的获取入口。

使用现有路由生命周期和 Manifest 缓存重新投影。新建规则从能力引导返回时，只保留当前页面实例、同账号和同会话 epoch 下的填写；账号/会话变化必须丢弃，不承诺页面销毁或 App 重启后恢复。查询失败时提供只读重新查询，不误报缺能力，不覆盖填写；既有编辑规则路径不新增能力跳转。原自动化执行、命名、权限、冲突及 unknown 语义保持。

服务端 `paused` 同时覆盖静默及部分不可用情况；App 已有“不代表停用或离线”的解释，本批不将其当作执行器缺失，不新增心跳、不放宽新鲜度准入、不重新设计服务状态合同。

### U4 任务未确认操作

主信息使用保存、删除、开始、授权同步等中文操作名。请求号与授权号进入可展开的技术详情；保留原 journal 和完整请求信息，只改变展示位置。

只读查询不执行旧操作；恢复原请求可能继续原操作；停止本机追踪不等于撤销设备任务。保持三个操作及其确认说明，不合并成含义不清的“重试”，不自动 Initialize、Start 或生成新请求号。当前四槽试点、UTC 来源未展示及重启中止等边界不因 UI 简化而改变。

## 5 BLE 测量和现场安全

已有 N3 三次大包进入样本为 2459/2632/2517 ms，六次开关回报为 82～121 ms。这是历史限定对照，不是本批数据，也不是秒开承诺。鉴权前仍用 20 B，ESP32 鉴权后才协商较大分片；不将 packet 上限等同于实际满包、DLE 或 2M PHY。

本批观测扫描、GATT、通知订阅、MTU、Hello/Noise/Method2、Manifest 协商/缓存与 fresh State、页面可控制。阶段可能嵌套或重叠，不把所有时长直接相加；没有发生的阶段标为未观测，不填 0 ms。Method2 与首次 Noise/认领分别记录，不为了计时清授权触发新认领。

先检查 ADB、已安装 debug App、当前账号和已有匹配授权。默认只进入/退出页面并观察，不刷板、不清授权、不切换用户网络、不修改服务。若存在匹配已绑定 BLE 设备，最多执行三次短进入并在每次退出确认连接释放。没有匹配授权或现场不可用时，记录阻断，软件回归继续；不自动创建新设备或借其他测试板身份代验。

工具记录阶段名、相对时间、成功/拒绝类别和缓存命中类别，不输出 token、DeviceKey、WiFi 密码、原生地址、payload 或任意异常正文。测量结束恢复原函数并移除观察器；超时不盲目重发，先检查残留测量与页面连接状态。

本批现场补充授权：用户无法确认现有匹配板，允许必要时清理 BLE 授权和重烧。实际操作收窄为已核对身份的 COM3 专用 XIAO：先新鲜完整 8 MB 备份和设备校验，只写临时 BLE 候选的 app0；候选使用既有隔离测试 namespace，优先复用测试授权，结束后恢复本批原 NVS/OTA metadata/app0 并校验。不全量删除 App/服务器历史设备表，不操作其他板；原账号和请求日志保留。隔离 namespace 仅用于有限测试，不成为生产 API。

### 10.4 瞬时发送背压修正及唯一剩余短验收

本节保留初次有限修复及其验收顺序；后续实物结果取§10.5，当前源码的最终背压边界和交付编译取§10.6。原失败与初次实现说明不改写为最终算法。

根因不是名称解析或NimBLE协商：Small BLE发送队列只有一个frame槽，原按钮回调先report计数、再emit Event；Event占槽后State Patch返回`WouldBlock`。原`OutboundScheduler::commitStateSelection`无论发送结果都清dirty，因此设备已有新值而BLE丢失通知，后续`AckPending`仍可成功。379兼容图和当前源码的相关Client/Outbound实现相同，不能归为仅旧固件问题。

最小修正只使用原dirty/selection、发送间隔和ACK链，不新增队列、成员、协议或App执行器：

- 仅发送结果为`WouldBlock`时保留dirty、清本次selection并更新时间；后续普通poll按现有`stateMinimumIntervalMs`重试（默认250 ms），期间report合并为最新值。其他原永久/重连错误处理不改。
- Client仅在已完成编码、revision推进、扇出及selection提交后的发送背压分支成功早退，结束本次force flushAll，保留后续投递；不能把已经执行的Action改为业务失败。共享settlement回调和早期workspace/apply冲突的`WouldBlock`语义保持原样。
- Event与Action不重放，原`AckPending`负责真实ACK。部分peer已成功时，保留的当前值按既有新revision重新扇出，可能重复送到Cloud；这不是同revision重传、事件可靠重放或exactly-once，Direct沿原revision-gap/StateRequest恢复。

冻结前审阅发现§10.4有限修复仍有边界，最终算法以本节为准，不能继续将“每次背压重试都推进新revision”作为推荐实现：

- 使用原dirty/selection、状态存储和250 ms发送间隔；`WouldBlock`只保留待投递值，不重放Action/Event或吞掉早期workspace/事务冲突。Client仅新增`uint32_t revision`及`size_t selectedCount`两个私有标量，无新增帧队列、位图、值副本或持久化内容。
- 同一已提交选集、没有真实新report且版本未变时，重试沿用该revision，不能制造分页或CAS冲突。真实变更及全量dirty刷新清除复用资格；已成功送出的首段与未选尾段不混用同版本。
- 成功Apply只在已有retained dirty时，把实际key/ID字段合并到原dirty。只有完整合并delta能单帧选择时才复用Apply真实新revision；不能以新revision只补旧字段而漏掉Apply字段。部分选择沿原版本/gap恢复机制处理，不增加协议。
- State扇出实际发生的`WouldBlock`优先于另一lane永久错误，无背压时保留原首错误语义；非State不改。真实版本变更及peer/session生命周期负责观察失效；同当前revision的重复投递失败不得清掉已有效的snapshot/cursor。删除fanout中这两处重复失效。
