## 1. 产品范围与单一权威来源

只展示**云端控制记录**，不是完整设备运行日志、审计事件流或串口日志。唯一来源是Broker现有`v2_command_ledger`；不新增活动表、采集器、后台worker或第二套执行链。

已核源码事实：`command.ts`在首次publish前建立ledger，从创建起设置7日TTL；`command-store.ts`仅在原命令生命周期更新尝试／结果，迟到真实ACK可把UNKNOWN推进为acknowledged。活动查询只SELECT，过滤已到期记录，不调用`initializeV2CommandRuntime`、recover、prune、replay、分配序号或发送命令。数据库只新增同表查询索引，不改保留期或原数据。

创建账本前就拒绝的操作、BLE／LAN直连、本地物理变化、任务进度及独立State不在本来源；现有云端自动化若进入同一命令引擎，可自然出现，但不按idempotency前缀猜测操作者／来源。账本没有可靠actor列或物理执行时间，不补造。来源缺失不等于用户从未操作，账本会到期、设备删除会级联清除，不承诺永久审计或完整7日活动。

## 3. 确认与未知结果语义

| 投影状态 | 页面短文案 | 不应声称 |
| --- | --- | --- |
| inflight | 处理中 | 已发送或已执行；attempt0可能尚在准入 |
| acknowledged | 设备已确认 | 新鲜State已同步、设备回调／物理动作已完成 |
| not_sent | 未下发 | 设备拒绝；只复用原NOT_SENT且attempt0的纯投影 |
| rejected | 请求被拒绝 | 所有拒绝都来自设备，或可安全自动重试 |
| outcome_unknown | 结果未知 | 失败、未执行、可以重发 |

复用原`commandStatus`纯投影语义：没有active owner的inflight对外呈未知，不写回账本。`createdAt`是服务器建立记录时间，`updatedAt`是最近尝试或结果变化时间，二者均不冒充用户点击、ACK专属时刻或设备执行时刻。页面本地时区显示，API保留原UTC epoch。
