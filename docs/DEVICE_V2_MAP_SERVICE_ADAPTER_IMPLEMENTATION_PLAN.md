## 1. 目标与当前事实

让普通用户不申请、不填写、不获取平台的服务器端私密 Key，也能在设备设置中查看和编辑位置。沿用已实现的位置持久化、owner 权限与 revision CAS；不改变设备通信、任务、自动化及 UNKNOWN 合同。

- 已完成：位置设置／读取／清除的后端链路及有限真实 App 验收；App 已改为地图优先、坐标输入折叠、未设置时询问、同意后一次手机定位作为草稿候选。
- MAP-4 新证据：托管底图／标注、真实拖动→保存→鲜读与取消已通过；§14 只修布局，署名真实可见、空态和前后台释放补证通过，原空位置以新 revision 正常恢复。§17 已另证当前手机系统网络取点成功，未单独验GNSS；公开手动测试点不当作手机定位，不再重复已通过的地图／持久化链路。
- 当前已安装 §17 系统定位修正的匹配 beta，位置页仅使用托管地图，不静默使用公共源；高级 BYOK 保持独立。**原 Gateway 同镜像及私有挂载保留，修正后运行开关已为 true；4500／UTC 日预算保持。** 不将平台 Key 填入用户本地存储或通过远程配置发给 App。
- 企业开发者身份不等于具体应用 Key 类型。实际申请应核对服务端调用方式、允许的图层、代理展示权限、配额和署名要求；技术上能访问不等于取得转供或缓存授权。[天地图官方接入说明](https://tianjin.tianditu.gov.cn/static/help/note.html)

## 2. 首期决定与边界

采用 **现有 Gateway 内的独立地图模块 + App 已登录 HTTPS 瓦片请求**。平台服务器端 Key 只由 Gateway 读取，App／APK／公开配置不包含该 Key；不新建地图微服务、容器、账号体系或数据库。

请求路径：`位置页面 → 有鉴权的 MapTileClient → Gateway maps → 固定天地图 HTTPS 图层`。

三个责任保持独立：

| 责任 | 复用或新增 | 不承担的责任 |
| --- | --- | --- |
| 设备位置 | 现有位置 API、owner 权限、CAS | 不按 IP 自动覆盖、不因底图失败改坐标 |
| 手机定位 | 现有一次性 PhoneLocationService | 不持续跟踪、不自动写设备位置、不依赖地图 Key |
| 底图展示 | 新地图适配模块、既有 Leaflet 组件 | 不转发设备控制、遥测、任务或自动化请求 |

首期只提供街道底图与文字标注；不加入搜索／逆地理编码、导航、卫星图、离线包、服务器／CDN 缓存或 Bulk。已有自定义页面组件不全面重写；本次先接设备位置页，后续有明确需求再复用同一图层工厂。

地图只提供通用底图，不返回用户保存的位置、设备信息或昵称，因此不额外建立“每块瓦片对应一个设备”的 ACL。查看／修改设备位置仍由原位置 API 鉴权，不能用“能看底图”代替设备授权。

## 3. 最小 HTTP 合同

以下合同已由 MAP-1／MAP-2 实施，并由 MAP-3 发布固定入口；MAP-3当批真实瓦片上游关闭，当前启用状态取§14。

| 接口 | 成功结果 | 限制 |
| --- | --- | --- |
| `GET /api/v2/maps/config` | 既有 JSON 信封中的公开配置 | 已登录用户；不返回 Key、密钥路径或上游 URL |
| `GET /api/v2/maps/tiles/{layer}/{z}/{x}/{y}` | 原始 PNG／JPEG 二进制 | 已登录用户；`layer` 仅 `base`／`annotation` |

- 仅精确路径和 `GET`／既有 CORS `OPTIONS`；不接收任意 URL、host、provider、Key、query 或多余路径。拒绝其他方法和非规范整数；`z` 初始 1～18，`x/y` 必须处于 `[0, 2^z)`，最终缩放范围以获准图层能力为准。
- 服务端将 `base/annotation` 固定映射为获准的 `vec_w/cva_w`；坐标使用既有经纬度，底图投影为 EPSG:3857。不做静默坐标偏移；偏移问题单独核对数据来源与服务坐标合同。
- 公开配置只含 `enabled`、provider 标识、图层、tileSize、缩放范围、投影、固定文本／批准链接的署名与公开配置版本，不接受任意 HTML。App 自行生成固定的同源接口路径，配置不得引导它把用户 Bearer 发向第三方。
- 未配置默认关闭：已鉴权的 config 返回 `enabled:false`，不返回样例 Key、不静默改用其他地图源。显式开启但私有配置无效时安全报错，不伪装成正常可用。
- 瓦片 200 不套 JSON／Base64。错误使用固定脱敏 JSON 与对应 400／401／403／405／429／502／503／504；上游鉴权失败不能伪装成用户登录失效。限额响应可附 `Retry-After`，客户端不自动重试。
- config、瓦片及错误均 `Cache-Control: private, no-store`；瓦片增加 `X-Content-Type-Options: nosniff`。不返回上游 `Location`、`Set-Cookie` 或原始错误内容，不将用户 token 放入 URL。

## 4. Service 最小接线

在 Service 的 `services/gateway/src/maps/` 内分离配置／合同、天地图适配、预算与 HTTP 生命周期；按实际职责合并小文件，不建立通用插件框架。`index.js` 只负责构造、精确路由和停机接线。

### 4.1 身份与资源隔离

- 复用现有 Aily 用户 Bearer 及身份加载链，不接受 DeviceKey、MQTT JWT 或内部服务凭据作为用户身份。具有管理员角色的正常用户 Bearer 仍按正常用户处理。
- 复用有效身份缓存与并发合并，不为每块瓦片强制请求 Auth；禁用失效权益快照兜底。再通过现有 tenant 查询确认 `active` 和所属用户匹配，服务账号删除流程中的身份拒绝进入。
- 既有 HTTP 适配 `resolveRequestIdentity` 会直接写错误，不能简单 `Promise.race` 后遗留迟到写响应。地图改用不接触响应的薄适配复用底层身份加载，在取消／截止后禁止写响应和启动上游；共享身份查询不因此被误取消，也不修改其他 API 的鉴权行为。
- 地图使用独立账号／全局预算命名空间，可复用现有 Redis 原子窗口；**不逐瓦片消耗原登录限流桶**。共享配额存储不可用时地图失败关闭，不放开付费上游请求。
- 不将代理后的 `socket.remoteAddress` 当成用户 IP，也不信任客户端自填转发头。首期以用户和全局限额为主，必要的 Nginx 边缘 IP 限流单独配置。

### 4.2 上游与 Key

- 平台 Key 通过只读私有文件挂载读取，公开仓库仅保留配置名及占位说明；不写镜像、构建产物、App 配置、设备固件或业务日志。轮换复用既有受控发布流程，不新建热更新系统。
- 适配器只构造固定官方 HTTPS 主机、固定图层与已校验坐标的请求；不透传用户 Authorization、Cookie 或客户端任意头。禁止重定向，不伪造浏览器来源来使用不适合的应用 Key。[OWASP SSRF 防护建议](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
- 校验实际流式读取字节数、图片类型、PNG／JPEG 魔数及声明的 256×256 瓦片尺寸；不能仅相信 Content-Length，也不允许小文件携带超大解码尺寸。200 的 XML／JSON／HTML／SVG 仍是错误；响应压缩解码后的字节数也必须有界。
- 从准入开始的整次截止覆盖等待、鉴权、上游 headers 和完整 body，不逐阶段重置。客户端断开、服务关闭或截止后释放队列／并发，终止上游；不复制现有部分客户端“收到 headers 即清 timer”的做法。
- 所有上游异常先收敛为固定 MAP 错误，避免含 `tk` 的 URL 或 error cause 进入全局 logger。保留请求 ID、阶段、状态、耗时、字节数，不记录精确坐标、视口路径、Key 或 token。

### 4.3 初始工程上限

下表是待有限回归核实的工程初值，**不是天地图官方配额或全进程 RAM 保证**。正式每分钟／每日总量必须按申请得到的额度明确配置，未配置不得开启。

| 对象 | 初始限制 |
| --- | --- |
| App 单地图会话，两图层合计 | 4 个并发、64 个等待；旧视口工作优先取消 |
| App 活跃 Blob | 最多 96 个 URL，压缩图片总量最多 16 MiB；解码图像另有浏览器开销 |
| Gateway 单实例地图工作 | 全局 16 个活跃、64 个等待，涵盖鉴权；身份确认后每账号至多 4 个上游活跃 |
| 单瓦片实际 body | 最多 512 KiB，超限中止而非继续下载 |
| 整次请求 | Gateway 10 秒，App 最多 12 秒；无自动重试 |
| 上游调用总量 | 每用户默认 120 次／分钟、300 次／日，全站默认 600 次／分钟；全站合并日预算显式配置且至多为确认单图层日额度的 90% |

并发与内存是实例内上限，付费请求总量通过共享预算约束；以后增加实例不能只复制本机限额而放大总额度。地图预算不得阻塞原控制／任务执行链。

日限额按上游瓦片请求计，不是打开页面次数；底图与标注各自消耗请求。上述用户／分钟数是可配置工程初值，不新增或修改 Free／Pro 权益。当前个人认证截图中两选定图层均为正常、分别 10000 次／日，因此配置默认 `MAPS_PROVIDER_LAYER_DAILY_LIMIT=10000`，合并 `MAPS_DAILY_UPSTREAM_LIMIT` 须显式设置且不超过 9000。两个图层合用一个较小预算是保守约束，不意味着官方将两图层共算 10000。企业认证未完成，不预支用户提及的 300 万额度；未来确认新额度后只改配置，不改预算执行器。用户要求运营统计按 UTC，因此 `MAPS_DAILY_UTC_OFFSET_HOURS` 默认及当前运行值均为 0（校验整数 -12～14，用户／全站日桶及 TTL 共用同一日界）。该选择不是上游额度重置日界的证明；若官方日界不同，启用前需明确与供应商保护窗口的对齐策略，不能声称 UTC 日预算必然约束任意供应商统计日。其他应用共用此 Key 的消耗不在本模块计数内。

### 4.4 公开入口与隐私

只在既有云端 Nginx 中精确增补地图路由，沿用 HTTPS／请求 ID／CORS；不增加公网端口或通用代理入口。现有 `$uri` 会记录 z/x/y，地图路由应改为不含坐标的专用日志或仅记录汇总；APM、错误栈和监控标签同样不得保留完整上游 URL／精确视口。

首期 Gateway、Nginx、CDN 与客户端持久缓存均关闭。不通过增加缓存规避尚未确认的授权；日后若获准共享底图缓存，仍需先完成用户准入与预算，不允许未登录者命中缓存绕过保护。

## 5. App 最小接线

- 新建小型 `MapTileClient` 与图层工厂，复用现有 `HttpClient`／ServerInterceptor。把固定 API authority 下的精确 maps 路由加入 `api.config.ts` 识别，不放宽任意 URL；第三方／BYOK 请求绝不附用户 Bearer。
- 普通 `<img src>` 无法附自定义 Bearer。使用 Leaflet 公开 `L.GridLayer.createTile(coords, done)`，保留两个参数的异步合同；HTTP Blob 通过类型／大小检查后生成 ObjectURL，图片加载后完成回调。[Leaflet 官方 GridLayer API](https://leafletjs.com/reference.html#gridlayer-createtile)
- 每请求新建 HttpContext，复用 `GATEWAY_NO_AUTH_REPLAY`；401 只停止当前地图队列并给一次登录提示，不自动刷新 token、重发瓦片或触发提示风暴。Blob 错误按 HTTP 状态归类，不假设能取得 JSON 业务码。
- 会话捕获账号、sessionEpoch、实际 API authority、页面与图层 generation；只向仍有效的前台会话交付结果。切页／后台／注销／环境变化／旧视口卸载均取消请求、清等待并回收 ObjectURL，迟到结果不更新 UI。
- 用真实订阅取消终止 XHR，而非只用 Promise.race 停等待。`tileunload` 处理单瓦片；`onRemove/dispose` 另行完整清理，不能只依赖事件。组件先显式 dispose 共享图层 owner，再解绑事件／删除地图；每瓦片 `done` 至多一次。
- 页面继续保持地图优先、拖标记／点图、折叠坐标输入、明确保存／取消。平台地图不可用时只给简洁状态与手动重试入口；不让普通用户去申请企业 Key，不静默切到 OSM 或用户 BYOK。
- 运营托管源与用户高级 BYOK 显式分离；保留已有高级消费者，不把平台 Key 塞入 `ActiveThirdPartyService.key` 或 localStorage。仅在确有第二消费者时复用同一小型图层工厂，不扩建 provider 插件系统。
- 原手机定位一次请求的权限暂停／返回处理独立保留；地图加载不重新触发定位，定位成功只填草稿，只有用户明确保存才调用原位置 CAS 写入。

## 7. 有限回归与短验清单
